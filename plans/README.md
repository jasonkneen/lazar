## Findings considered and rejected

(So nobody re-audits them.)

- **`append_stream` per-event I/O** (re-open + flock + rotation stat on every
  event — including a redundant double `symlink_metadata` on stream.jsonl
  per append and per-event env parsing; ~10 cycles per hooked tool call):
  real but negligible next to API round-trip latency; restructuring to a
  held handle/process-once caches complicates the multi-process locking and
  rotation-deadlock guards for sub-millisecond wins. Not worth doing.
- **Subprocess poll-wait loops** (`run_bash` 50ms, `run_hook` 20ms): bounded,
  simple, appropriate; event-driven reaping risks regressing the
  process-group-kill + capped-pipe-drain choreography. Not worth doing.
- **Per-turn content clones / double serialization** (assistant `content`
  cloned twice per turn; session-mirrored events serialized once per sink):
  bounded per turn, small next to the SSE fix in 002. Executors of 002/006
  may fold in a free win if the lines are already under edit; not a
  standalone plan.
- **Missing `set -e` in several skill scripts** (`lazar-spawn`,
  `keychain-*.sh`, `harvest.sh`, selftests, eval scripts): deliberate — they
  do manual return-code accounting and would abort mid-suite under `-e`.
  Worth a one-line `# no set -e: manual rc accounting` comment when those
  files are next touched; not a plan.
- **LAZAR_HOME guard prologue / `fail()` / rsync-src-apply blocks duplicated
  across setup + ceremony scripts**: accepted duplication — each ceremony
  script must run standalone (they execute before/without the skills tree),
  and a sourced `scripts/lib/` adds a failure mode to chflags/rm -rf paths.
  The one high-value dedup (the build+atomic-swap+lock sequence) is plan 010
  via delegation, not a lib.
- **Shared test-harness lib for the five `ok()/no()` selftest scaffolds**:
  rejected for the same reason — seed skills are documented as individually
  portable (README "Skills are portable"); a cross-skill `_lib/` breaks
  copy-one-folder portability to save ~4 lines per script.
- **Nudge-filter chain duplicated between `seed-hooks/session-start.d/05-recent-activity.sh`
  and `log-harvest/harvest.sh` (and already drifted)**: real drift, but a
  shared pattern file couples a sandboxed hook to the skills tree and breaks
  skill portability. Cheapest durable fix: cross-referencing comments in both
  files naming the other copy — do it when either file is next edited.
- **`extract_bash_fences` hand-rolled scanning** (main.rs:136-178): verbose
  but correct, tested, dependency-free; a regex rewrite adds a dependency for
  no behavior gain.
